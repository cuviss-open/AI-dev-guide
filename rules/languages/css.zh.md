# CSS 规则

## 目标

本规则适用于手写 CSS。目标是让样式文件可删除、可迁移、可审查，避免单个全局 CSS 文件持续膨胀。

## 文件大小

- 手写 CSS 文件不得超过 1000 行。
- 900 行以上应优先拆分，不继续追加大段规则。
- 聚合入口文件只放 `@import`，不继续写业务样式。
- 生成文件、第三方产物和构建产物不受本规则约束，但除非项目明确要求，不应提交到 Git。

## 文件边界

- 组件专属样式跟组件或领域目录走。
- 跨页面基础样式放在共享 styles 目录。
- 第三方 UI 库全局覆盖集中到明确命名的 override 文件，或按领域拆分。
- 静态页面样式可保留集中入口，但应按 base、layout、content、component、responsive 等职责拆分。
- 不为压行数制造无意义拆分；拆分边界应按布局、组件、主题、覆盖层或响应式职责划分。

## 主题规则

- 一个主题一个文件，避免多个主题混在一个大文件里。
- 主题索引文件只作为 `@import` 聚合入口。
- 主题 ID、展示名、默认主题和可选主题列表应有单一来源。
- 默认主题 CSS 必须提供应用启动可用的基础变量。
- 新增、删除或重命名主题时，同步主题 CSS、主题索引和主题元数据。
- 删除主题时确认代码内没有残留主题 ID 引用。

## 导入顺序

- 拆分 CSS 必须保持原级联顺序。
- 修改聚合入口时，对比展开后的内容，确认没有丢规则或改变顺序。
- CSS `@import` 路径必须相对当前 CSS 文件，而不是相对 TS/TSX 调用方。

## 验证

修改 CSS 后至少执行：

```bash
rg --files -g '*.css' | while read -r f; do n=$(wc -l "$f" | awk '{print $1}'); if [ "$n" -gt 1000 ]; then echo "$n $f"; fi; done
```

涉及前端样式或主题变更时，还应运行项目对应构建、类型检查或样式验证命令，例如：

```bash
npm run build
```
