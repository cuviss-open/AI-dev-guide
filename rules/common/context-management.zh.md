# 上下文管理规则

## 读取策略

- 先读索引、目录和文件名，再读具体文件。
- 先用关键词搜索，再打开命中的小段落。
- 优先读取行范围，不默认通读大文件。
- 同一任务内，已读文件若修改时间和大小未变化，可以复用已读内容或摘要，不必反复读取全文。
- 不复制长源码、长日志或长文档到回复中。
- 不复述与任务无关的背景。

## 缓存判断

复用已读内容前，先确认：

- 文件路径相同。
- 文件修改时间未变化；可同时参考文件大小或 Git diff 状态。
- 当前判断不依赖刚执行命令产生的新输出。
- 该文件不是密钥、缓存、日志、本地数据库或其他禁止进入上下文的内容。

以下情况必须重新读取相关小段落：

- 文件由用户、AI、格式化器、生成器或测试命令改动过。
- 工作区状态显示文件已变化。
- 任务需要精确行号、精确报错或最新配置值。
- 上次读取只是摘要，当前需要核对具体代码或规则。

## 命令输出压缩

长命令输出应优先在源头降噪：

- 优先使用命令自带的 quiet、short、json、失败摘要或结构化输出选项。
- 测试和构建失败时，先保留失败文件、断言、行号、错误码和最短堆栈，再省略重复进度、成功用例和安装噪音。
- 可以使用本地、确定性、可审查的命令输出压缩器；压缩器不得成为项目运行的强依赖。
- 压缩器必须能保留或回看原始输出，尤其是失败日志、编译错误、测试断言差异和迁移输出。
- 不得把密钥、真实 `.env`、本地缓存、本地数据库、个人路径或账号数据发送给云端 LLM 做摘要。
- LLM 摘要只适合人工明确要求后的二次分析；不得把它作为默认自动过滤层或唯一事实来源。

如果压缩后仍无法定位问题，重新读取未压缩输出中的相关小段落，而不是扩大到整段日志。

## 扩展上下文

只有在当前最小上下文无法判断时，才继续读取更多文件。

扩展前先确认：

- 新文件与当前任务直接相关。
- 不会读取密钥、缓存、日志、本地数据库或其他敏感内容。
- 可以用更窄的搜索或行范围替代全文读取。

## 输出上下文

最终回复只报告和任务结果有关的信息：改动、验证、风险和下一步。不要把读到的规则、源码或背景整段复述给用户。
